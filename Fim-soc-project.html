01Overview

DETECTION

Why FIM matters

Unauthorized changes to critical files are a common signal of malware, persistence mechanisms, privilege escalation, or insider activity. FIM gives a SOC visibility into exactly what changed, when, and how.

SCOPE

What this lab covers

Single-node Wazuh deployment via Docker, syscheck configuration for real-time monitoring of /root, and validation of the full alert pipeline from agent to dashboard.

STACK

Components

Wazuh Manager 4.14.5, Wazuh Indexer, Wazuh Dashboard — orchestrated with Docker Compose on a single host.

03Configuration

FIM is enabled through the <syscheck> block in the manager's shared agent configuration, which propagates to every connected agent. 

/* /var/ossec/etc/shared/default/agent.conf */
<agent_config>
  <syscheck>
    <disabled>no</disabled>
    <frequency>43200</frequency>
    <directories check_all="yes" report_changes="yes" realtime="yes">/root</directories>
  </syscheck>
</agent_config>

check_all="yes"

Checks every file attribute — permissions, owner, group, size, and cryptographic hash.

report_changes="yes"

Stores a diff of file content changes for forensic review.

realtime="yes"

Uses inotify on Linux for instant detection instead of waiting on the scheduled scan.

04Deployment

  1. Stand up the Wazuh stack

    Deploy the single-node Docker Compose configuration containing manager, indexer, and dashboard.

    docker compose up -d

  2. Push the FIM configuration to the manager

    Copy the updated shared agent config into the manager container and restart.

    docker cp agent.conf single-node-wazuh.manager-1:/var/ossec/etc/shared/default/agent.conf docker exec -it single-node-wazuh.manager-1 /var/ossec/bin/wazuh-control restart

  3. Restart the agent

    The agent pulls the new shared configuration on restart.

    systemctl restart wazuh-agent

  4. Confirm the merged configuration

    Verify the monitored path appears in the agent's merged config.

    cat /var/ossec/etc/shared/merged.mg | grep -A2 syscheck

06Key takeaways

  • FIM is only as reliable as the full pipeline — manager, indexer, and dashboard all need to be healthy for alerts to surface.
  • Real-time monitoring depends on inotify, which should be tuned for production workloads.
  • Configuration changes propagate manager → agent via agent.conf, and agents must be restarted to apply them.
  • End-to-end validation — agent log → alerts.json → indexer → dashboard — is the fastest way to isolate a broken stage.
